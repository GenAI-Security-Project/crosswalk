# External Benchmarks

Published benchmarks and evaluation corpora that test GenAI systems for the risks this
crosswalk maps. They are catalogued here so a reader can find them; **none of them ships
as a profile in this repository.**

## What this file is not

- **Not runnable from here.** Nothing below is a Garak probe, a PyRIT script or a LAAF
  stage. Each is published by its own authors with its own harness and licence, and is
  run from there. `evals/garak/`, `evals/pyrit/` and `evals/laaf/` remain the only
  runnable profiles.
- **Not threshold-bearing.** [`THRESHOLDS.md`](THRESHOLDS.md) covers the profiles this
  repository runs. A pass mark for someone else's benchmark is theirs to set, not ours,
  so no value is recorded here.
- **Not an endorsement or a reproduction.** The figures below are the authors' own,
  transcribed from each paper's abstract. Nothing has been re-run.
- **Release and licence are as stated by the authors.** Where the Source column names
  a release, the link was checked to resolve when the row was added; the licence is the
  one the release declares, or "none stated". A release the paper promises but has not
  published is recorded as not released.

## The OWASP entry column is DRAFT

> **DRAFT — SME review required.** The entry each benchmark is listed against is a
> reading of the benchmark's stated scope, not a reviewed mapping. A reviewer should
> confirm or correct it before anything downstream relies on it.

## Catalogue

| Benchmark | What it measures | Scale, as published | OWASP entry (DRAFT) | Source |
|---|---|---|---|---|
| **LongPIBench** | Prompt injection in **long-context** settings, which short-context benchmarks leave unexplored — the authors argue that gap "leads to a substantial overestimation of the effectiveness of current defenses" | 4 realistic application scenarios — paper peer review, resume screening, code review, email summary — each with a synthetic and a real-world dataset, context lengths from thousands to tens of thousands of tokens | LLM01 Prompt Injection | [arXiv:2608.28411](https://arxiv.org/abs/2608.28411) |
| **GenIaC-SecBench** | Security of **LLM-generated Infrastructure-as-Code**, against a human baseline, so results say whether models are worse than engineers rather than reporting raw vulnerability counts | 100 deployment scenarios stratified by architectural complexity; 12 model configurations from 4 vendors; 1,196 IaC artifacts; 3 independent scanners | LLM10 Improper Output Handling | [arXiv:2608.28021](https://arxiv.org/abs/2608.28021) |
| **TIER** | Behavioural safety across **threat implicitness**, replacing binary refuse/comply metrics with a graded scale — the authors find "safety behaviors evolve gradually across threat levels rather than shifting directly from refusal to compliance" | 4 risk domains × 4 threat levels, from explicit harmful requests to sophisticated jailbreaks; 6-label behaviour scale; 2 independent LLM judges; 6 open-weight models | LLM01 Prompt Injection | [arXiv:2609.05117](https://arxiv.org/abs/2609.05117) |
| **APort Vault** | **Payment authorization** in tool-using agents: whether human-written attacks get an agent to request or execute payments, with and without a deterministic pre-action check implementing the Open Agent Passport (OAP) specification; reports five distinct events per evaluation rather than one collapsed number | 4,371 attacks written by humans against a live payment agent during a public capture-the-flag event; 14 models from 8 labs; five policy configurations; two replay tracks; 225,964 evaluations | LLM01 Prompt Injection · LLM03 Excessive Agency · ASI02 Tool Misuse and Exploitation | [arXiv:2609.22076](https://arxiv.org/abs/2609.22076) · release: [aporthq/vault-benchmark-v1](https://huggingface.co/datasets/aporthq/vault-benchmark-v1) (CC BY 4.0; access-gated). The paper's disclosure section states that the author founded the company that develops the authorization layer evaluated, and that the benchmark was designed, run and analysed by the author. |
| **ClashBench** | **Destructive resource preemption**: whether an agent obtains resources for a requested task "by terminating, overwriting, evicting, or degrading an incumbent task" rather than reporting the conflict | 268 validated conflict cases across 55 resource types; 17 models evaluated through Codex, Claude Code and OpenCode | LLM03 Excessive Agency · ASI02 Tool Misuse and Exploitation | [arXiv:2609.19892](https://arxiv.org/abs/2609.19892) · release: [TarferSoul/CLASHBench](https://github.com/TarferSoul/CLASHBench) and [jinjinyien/CLASHBench](https://huggingface.co/datasets/jinjinyien/CLASHBench) (licence: none stated) |
| **AgentLSD** | **Adversarial task contamination** of AI security agents — deceptive artifacts in the environment, including non-instructional evidence "such as fake results and decoy endpoints", rather than injected instructions alone | Paired clean and trap-augmented runs on CTF challenges with deterministic trap generation; 6 models on 11 web CTF challenges | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2609.19140](https://arxiv.org/abs/2609.19140) · release: [Golim/agent-lsd](https://github.com/Golim/agent-lsd) (MIT) |
| **AgentXploit-Bench** | **End-to-end exploitability of AI-agent systems** in authorized white-box pre-deployment auditing: attacks must act through the task-defined attacker interface and be confirmed by an external verifier | 72 reproducible vulnerabilities across 12 open-source AI-agent systems and frameworks | ASI02 Tool Misuse and Exploitation · ASI05 Unexpected Code Execution · LLM01 Prompt Injection | [arXiv:2609.31318](https://arxiv.org/abs/2609.31318) · release withdrawn: the `lwd17/AgentXploit` repository, catalogued on 2026-09-30 (its README then stated Apache-2.0, with no licence file), returns 404 as of 2026-11-25, and the arXiv record links no other release |
| **PrivDrift** | **User-secret leakage under topic drift**: whether secrets a user disclosed earlier in an active conversation remain recoverable after the dialogue moves on, under persuasion-based probing | 1,000 controlled multi-turn dialogues with seeded secrets, content-dense drift turns and standardized extraction probes; 3 LLMs with extended context windows | LLM02 Sensitive Information Disclosure · DSGAI11 Cross-Context Conversation Bleed | [arXiv:2609.30094](https://arxiv.org/abs/2609.30094) · not released: the paper states the authors "plan to release" the generation code, probes, scripts and a sanitized subset |
| **EvoRiskBench** | **Runtime security risks in workspace agents** — models combined with execution harnesses that perform stateful, multi-step tasks on external resources — organised around the authors' EP-Path-EF framework, which "links an initial risk entry point to a one-hop technical effect through an agent-mediated risk path"; outcomes are verified independently from runtime traces and environment states | 450 adversarial tasks across six scenarios; nine entry-point and five effect categories; 9 model-harness configurations (3 models × Claude Code, Codex and OpenClaw) | ASI02 Tool Misuse and Exploitation · ASI05 Unexpected Code Execution | [arXiv:2610.03153](https://arxiv.org/abs/2610.03153) · not released: the paper states the cases and platform "will be released after completion of artifact safety and reproducibility checks" |
| **PAGE** (Persona-Aware Guardrail Evaluation) | **Function-specific guardrails** for customer-facing agents: whether a guardrail keeps an agent within its intended functionality, across "benign, adversarial, and out-of-domain interactions on both user and agent turns" | Not stated in the abstract | LLM01 Prompt Injection · LLM03 Excessive Agency | [arXiv:2610.03434](https://arxiv.org/abs/2610.03434) · not released: the arXiv record links no benchmark release. The benchmark is introduced alongside, and used to evaluate, the authors' own guardrail (Persona Guardrail), which the paper states is deployed in production. |
| **STEER-Bench** | **Branch steering** against computer-use agents: whether crafted untrusted data can "coerce a CUA down a hazardous, pre-approved branch without injecting explicit instructions", including agents built on the Dual-LLM planner/quarantine pattern | 101 tasks across 9 domains; the authors report 94.4% attack success against standard and 89.5% against vanilla Dual-LLM agents | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2610.03089](https://arxiv.org/abs/2610.03089) · not released: the arXiv record links no benchmark release. The benchmark is introduced alongside the authors' own defense (COBRA), which they report reduces attack success on it to 0%. |
| **AgentThreatBench** | Whether **LLM agents complete useful work while resisting adversarial content** in tool outputs and memory stores, scored separately for utility and security | 3 Inspect AI tasks: memory poisoning (10 samples), email-triage goal hijack (6 samples), customer-support data exfiltration (8 samples); each includes clean baselines | ASI06 Memory and Context Poisoning · ASI01 Agent Goal Hijack | release: [UKGovernmentBEIS/inspect_evals, agent_threat_bench](https://github.com/UKGovernmentBEIS/inspect_evals/tree/main/src/inspect_evals/agent_threat_bench) (MIT). Contributed by the PR author, who also co-leads OWASP Agent Memory Guard. |
| **APEX-Harm** | **Prompt and script injection against long-horizon agents** doing professional work: "a benchmark for evaluating prompt and script injection against long-horizon agents performing finance, consulting, and legal tasks in large workspaces", scoring attack success, exposure and task performance together | 180 task instances per model across 6 attack categories; workspaces of 115 to 328 files per task, with email, calendar, chat, document, spreadsheet, PDF and code-execution tools exposed through MCP servers; 12 frontier models | LLM01 Prompt Injection · ASI01 Agent Goal Hijack · ASI05 Unexpected Code Execution | [arXiv:2610.13623](https://arxiv.org/abs/2610.13623) · not released: the arXiv record links no benchmark release |
| **MobileInject** | **Multimodal injection against mobile agents**, where adversaries "embed malicious objectives in cross-application mobile content": "the first benchmark for evaluating mobile agents against multimodal injection attacks and reasoning-to-action security risks" | 108 executable risk instances across 11 scenarios and 9 security-risk categories | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2610.23307](https://arxiv.org/abs/2610.23307) · not released: the arXiv record links no release; the abstract states "Code release details are provided in the Appendix Open Science section" |
| **MobileJailBench** | **Jailbreaks of mobile agents inside real app workflows**, rather than in conversation: "the first evolving jailbreak benchmark for mobile agents" | 520 tasks across 3 jailbreak paradigms and 14 risk categories, on workflows in "over 20 widely used apps"; the task set evolves, so the count is a snapshot | LLM01 Prompt Injection · ASI02 Tool Misuse and Exploitation | [arXiv:2610.23303](https://arxiv.org/abs/2610.23303) · not released: the arXiv record links no benchmark release |
| **NTBench** (Near-Target Benchmark) | **Near-target prompt injection**: "attacks seeking responses designed to resemble legitimate answers while introducing incorrect or harmful changes", in responses and in agent tool invocations | 2 tracks (incorrect and harmful targets) built on legitimate tasks from existing datasets; 7 LLMs on 10 language-task datasets plus 2 agent benchmarks, with 3 attack executions per sample | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2610.32531](https://arxiv.org/abs/2610.32531) · not released: the arXiv record links no benchmark release. Built on existing datasets, whose licences would carry over to any release. |
| **AgentPhishing** | **Phishing against LLM email agents under adaptive attack**: "whether persuasive phishing attacks can evade detection and induce LLM email agents to comply with malicious requests" | 9 email agents; the authors report that four "exhibit phishing-detection rates below 10% and malicious-request compliance rates above 45%" | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2610.31404](https://arxiv.org/abs/2610.31404) · not released: the arXiv record links no benchmark release. The benchmark is introduced alongside the authors' own attack, PhishOpt, which "optimizes reusable email-generation skills against individual agents". |
| **AfterDeleteBench** | **Information that survives deletion in agent memory**: "Deleting an original memory record therefore need not remove information carried by its descendants", such as summaries; it compares "an exposed-then-deleted agent with an otherwise matched agent that was never exposed". The authors call it "a controlled behavioral audit" | Not stated in the abstract; models named are Qwen2.5-7B-Instruct, plus Qwen, Mistral and Phi-3 models. The authors report a single query recovers the deleted secret "in roughly two thirds of cases", with zero recovery for never-exposed controls | DSGAI07 Data Governance and Lifecycle · LLM02 Sensitive Information Disclosure | [arXiv:2610.31366](https://arxiv.org/abs/2610.31366) · not released: the arXiv record links no benchmark release. The authors evaluate mitigations on it, reporting that "Provenance-aware closure eliminates observed recovery in the tested positive-baseline settings". |
| **Omni-UBench** | **Omni-modal guardrail models**, scored on "three critical dimensions, i.e., safety, utility, and reliability"; the authors report guardrails "struggle to identify cross-modal queries that conceal harmful intent or involve sophisticated jailbreaks" | "over 183k samples drawn from 35+ heterogeneous sources" across text, image, audio, video and cross-modal combinations, under a unified risk taxonomy; 15 omni-modal LLMs and guardrails | LLM01 Prompt Injection | [arXiv:2610.31713](https://arxiv.org/abs/2610.31713) · not released: the arXiv record links no benchmark release. Built from 35+ existing sources, whose licences would carry over to any release. |
| **SkillRelayBench** | **Cross-session attacks through agent skill composition**, where "malicious effects propagate across skill executions via persistent artifacts" such as files, configurations and cached data | 270 adversarial cases from 30 cross-session skill-composition scenarios across 10 domains; 7 models across Codex CLI, Gemini CLI and Claude Code, with attack success rates of 46.7% to 77.4% | ASI06 Memory and Context Poisoning · AST06 Weak Isolation | [arXiv:2610.13227](https://arxiv.org/abs/2610.13227) · not released: the arXiv record links no benchmark release. The benchmark is introduced alongside the authors' own defense (SkillRelayGuard), which they report "reduces overall ASR from 69.5% to 10.9%" on it. |
| **TrojanBench** | **Repository poisoning against coding agents**: "a benchmark of 384 poisoned repositories", on which the authors find "even commercial agents fail to defend against repository-level poisoning" | 384 poisoned repositories across 6 domains and 9 programming languages; 4 harnesses and 12 models | LLM01 Prompt Injection · ASI04 Agentic Supply Chain | [arXiv:2610.23109](https://arxiv.org/abs/2610.23109) · not released: the arXiv record links no benchmark release. The benchmark is introduced alongside the authors' own attack framework (TrojanForge), which they report "achieves a stable poisoning success rate of over 60%". The released corpus would itself be poisoned code. |
| **REEF** | **Injection attacks on web agents, verified through real state changes** rather than at the text level: "a benchmark of red-teaming executable environments with faithful verification for measuring the security vulnerabilities of web agents" | 9 verifier-grounded websites spanning travel, commerce, productivity, media and communication; every benign task paired with a malicious objective delivered through 5 attack types at both the user and the environment level; 8 VLM-based web agents | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2610.41272](https://arxiv.org/abs/2610.41272) · not released: the arXiv record links no benchmark release. The benchmark is introduced alongside the authors' own attack (ANGLER), "an adaptive near-miss-guided lure evolution framework for red-teaming", which they report achieves an end-to-end attack success rate of 20.36%, against 15.24% non-adaptive. |
| **YoloFS-Ext** | **Approval of coding-agent shell commands** when "harmful behavior is hidden inside invoked tools", so the text of the request and command does not reveal it; each dangerous task has a safe twin | Not stated in the abstract | ASI05 Unexpected Code Execution · ASI02 Tool Misuse and Exploitation | [arXiv:2610.40753](https://arxiv.org/abs/2610.40753) · not released: the arXiv record links no benchmark release. The benchmark is introduced alongside the authors' own defense (Caper), a consequence-aware approval mechanism that "pre-executes each command in a snapshotted sandbox", which they report reaches a 7.8% harmful-outcome rate on it, against at least 35.3% for six existing systems, while blocking 1.0% of the safe twins. |
| **RiskyPy** | **Joint security and functionality of LLM-generated code**, using datasets calibrated to the proficiency of the models under study. RiskyPy is "an automated pipeline that generates security-oriented code-generation datasets calibrated to model proficiency using functionality and vulnerability canaries", not a fixed corpus | The authors' Python instantiation: 101 prompts in domains covering 18 CWEs from the 2025 CWE Top 25; 2 models (Qwen3-4B, Seed-Coder-8B), with 57–72% of prompts yielding functional code and 5–10% of generations free of Bandit findings. A dataset generated for other models would differ | LLM10 Improper Output Handling | [arXiv:2610.40735](https://arxiv.org/abs/2610.40735) · not released: the arXiv record links no release |
| **MemoryDojo** | **Memory poisoning in LLM agents**: "a benchmark for tracing the lifecycle of poisoned information through agent memory and measuring its influence on subsequent agent behavior", across memory architectures | 155 multi-session long-horizon trajectories covering 4 domains; supports 5 memory systems; described by the authors as "easily extensible" | ASI06 Memory and Context Poisoning · LLM01 Prompt Injection | [arXiv:2611.09721](https://arxiv.org/abs/2611.09721) · not released: the arXiv record links no benchmark release. The authors also propose "a memory-aware poison optimization process that increases the poisoning efficacy". |
| **Authorization Drift Benchmark** (ADB) | **Agents exceeding their authorization boundaries without an adversary** — "authorization drift across data, tool, scope, and time" — where each task offers both a compliant path and an unauthorized shortcut | 648 samples across 7 domains, each "pairing a sufficient compliant path with an attractive unauthorized shortcut"; 13 LLMs and 3 frameworks (25,207 trajectories), with frontier-capable models drifting at rates of 0.43 to 0.61 | LLM03 Excessive Agency · ASI02 Tool Misuse and Exploitation | [arXiv:2611.09113](https://arxiv.org/abs/2611.09113) · not released: the arXiv record links no benchmark release |
| **Task-Tampering Prompt Injection** | **Indirect prompt injection that tampers with the task in progress** rather than redirecting it, defined "by authority rather than instruction-like wording": planted content is an attack "when it attempts to influence a decision that its source is not authorized to determine". The paper does not name the benchmark; this is the name of its release | 90 validated cases across 3 tool-use environments, with attacks targeting up to six parts of the agent's decision making; 5 LLMs. The authors report a tool-policy defense "still allows 15.4% attack success, close to 17.0% without a defense" | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2611.07640](https://arxiv.org/abs/2611.07640) · release: [amazon-science/task-tampering-prompt-injection](https://github.com/amazon-science/task-tampering-prompt-injection) (CC BY-NC 4.0 for the authors' code and data; third-party components retain their own licences) |
| **JailBound** | **Jailbreak robustness, including how behaviour changes locally between safe refusal and unsafe response**: "a unified jailbreak evaluation framework that combines automated benchmark construction with first-order loss (FOL)-guided dual-branch search", organising threats by risk category, application domain and attack type | Prompts are synthesized by a fine-tuned meta-attack generator, so the set is generated rather than fixed; its size is not stated in the abstract. 46 LLMs from 13 model families | LLM01 Prompt Injection | [arXiv:2611.07530](https://arxiv.org/abs/2611.07530) · not released: the arXiv record links no benchmark release. The benchmark is built together with the authors' own attack search (FOL-guided dual-branch search), whose High-Value Branch they report "improves average ASR over a ZOL-only baseline by 5.1 and 4.9 percentage points across the two evaluation settings". |
| **AgentAbstain** | **Warning-induced over-abstention in tool-using agents**: "an availability attack in which adversaries place fabricated risk warnings in low-trust content to prevent legitimate task completion" | 51 injectable task pairs, as controlled counterfactual variants of risk content, source provenance and warning wording; 3 model families. The authors report induced over-abstention for Gemini rising from 9.8% to 86.3% under caution-first prompting | LLM01 Prompt Injection · ASI01 Agent Goal Hijack | [arXiv:2611.14864](https://arxiv.org/abs/2611.14864) · not released: the arXiv record links no benchmark release. The benchmark is introduced with the authors' own attack (warning-induced over-abstention) and defense (a Verify-Before-Abstain protocol that "corroborates warnings against authoritative records or the underlying content"), which they report "improves legitimate completion". |
| **ROGUE-AI** (Replication of Agentic Security Events: Audit and Investigation) | **Replication of reported agent incidents**, as an audit framework rather than a fixed benchmark: "a multi-agent framework" that "rebuilds each reported incident offline together with a matched control that lacks only the blamed cause, and runs agents on both". The authors describe the replications as "a reusable audit framework that vendors can rerun before each new release" | 108 attempted replications, of which the authors report 89% reproduce the reported harm; agents on 5 GPT, Claude, Gemini and DeepSeek models made the reported mistake in 18% to 33% of runs, against at most 1% without the blamed cause. Of 72 incidents with real-world harm, 62 had no underlying attacker | LLM03 Excessive Agency · ASI02 Tool Misuse and Exploitation · LLM01 Prompt Injection | [arXiv:2611.26553](https://arxiv.org/abs/2611.26553) · not released: the arXiv record links a project page ([rogue-ai.surge.sh](https://rogue-ai.surge.sh)) that links no code or data release and states no licence |
